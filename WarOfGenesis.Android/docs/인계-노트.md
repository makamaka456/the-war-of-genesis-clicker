# 인계 노트 — 창세기전3 리메이크 안드로이드판

이 문서 하나로 다음 사람(또는 다음 세션)이 이어서 작업할 수 있게 적는다. 더 자세한 결정 · 경위는 `포팅-계획.md`,
검수 결과는 `검수-보고.md`, iOS 포팅에서 배운 것은 `iOS-포팅-참고.md` 에 있다.

적은 날: 2026-11-13 · 앱 판: 0.1.0 · 합친 원작 판: v1.1.4

---

## 1. 한 줄 요약

원작(PC, .NET WinForms + Direct3D 11)의 `duel-dx/` · `WarOfGenesis.Assets/` 소스를 **고치지 않고 링크**해서 .NET for Android 로 굽는다.
윈도우 전용 부분(창 · 메시지 · D3D11 · GDI+ · waveOut · WinForms · XInput)만 `Platform/` 의 작은 대용품이 같은 이름으로 받는다.
원본 게임 자료는 APK 에 없다 — 사용자가 폰에 넣은 원본 폴더를 앱이 읽는다.

## 2. 지켜야 할 것

- **원본 게임 자료(파트1 · 파트2 폴더, 원작자 꾸러미)는 APK · 공개 저장소 · 공개 릴리즈에 절대 넣지 않는다.** 시험용 자료는 공개되지 않는 곳에서만 쓴다.
- 원본 코드는 될 수 있으면 안 고친다. 꼭 필요하면 `#if ANDROID` / `#if !ANDROID` 로 작게, 고친 곳은 `포팅-계획.md` 의 목록에 적는다(원작 업데이트를 합칠 때 살핀다).
- 안드로이드 판 태그는 반드시 `android-vX.Y.Z` — PC 판 태그(`v*`, release.yml)와 섞이면 안 된다.
- `TheWarOfGenesis.sln` 에 안드로이드 프로젝트를 넣지 않는다(안드로이드 워크로드 없는 PC 빌드가 깨진다).

## 3. 폴더 구조 (`WarOfGenesis.Android/`)

| 자리 | 하는 일 |
|---|---|
| `WarOfGenesis.Android.csproj` | 원본 소스 링크(`<Compile Include="..\duel-dx\**\*.cs" Exclude=…>`), 함께 싣는 파일(assets · 릴리즈 노트), 해독기 .so |
| `MainActivity.cs` | 런처 — 「폴더 고르기」 하나. 고른 폴더 **안의 파일을 보고** 파트2 · 파트1 · 자료 폴더를 찾는다(이름은 안 본다). 골라 두었으면 곧장 게임으로 |
| `Game/GameSetup.cs` | 원본 자리 · 자료 폴더 저장/불러오기, 찾기 규칙, 환경 변수(`WAROFGENESIS_ORIGINAL` · `WAROFGENESIS_PART1` · `DUELDX_SAVEDIR`)로 원본 코드에 넘기기 |
| `Droid/GameActivity.cs` | 게임 스레드(원본 `GameWindow.Run()`), 화면(뒷버퍼 → Bitmap), 단축 아이콘, 도구 목록 창, 배경 그림, 대화 상자 |
| `Droid/Input.cs` | 터치 → 마우스(탭 = 한 묶음 클릭 · 길게 = 우클릭 · 두 손가락 = 휠/우클릭), 키 매핑, 패드 → XInput 자리 |
| `Droid/AndroidPlatform.cs` | 글자(Paint), 그림 해독(BitmapFactory), 소리(AudioTrack), mp3 해독(MediaCodec) |
| `Droid/KeepAlive.cs` | 메모리 정리(뒤로 갈 때 · OnTrimMemory), 알림줄 서비스(다른 앱에 다녀오는 동안 게임 유지 — 최근 앱에서 밀어 닫으면 끝낸다) |
| `Droid/Restart.cs` | 프로세스 새로 띄우기(:restart 프로세스) — 「원본 폴더 다시 고르기」, 끝난 게임에 다시 들어왔을 때 |
| `Platform/Win32.cs` | 가짜 Win32 — 메시지 줄(`PlatformHost`), 메뉴, 키 상태, 60Hz 틀 맞추기, `Batch`(메시지 묶음), `TouchHeld` |
| `Platform/Vortice.cs` | 가짜 D3D11 — CPU 합성(판 셰이더 글에서 배율 · 위치를 읽는다), HiCanvas 층 |
| `Platform/Drawing.cs` · `Forms.cs` | 가짜 System.Drawing · WinForms(MessageBox · 폴더 고르기 → 안드로이드 창) |
| `Platform/AudioMixer.Android.cs` · `GamePad.Android.cs` | 원본 `partial` 의 waveOut · XInput 자리 |
| `Platform/Replaced.cs` · `Removed.cs` | 윈도우 전용 원본 파일의 대용(같은 이름) · 뺀 기능(자동 업데이트 · 버그 리포트 · 편집기 · 고해상도 배경 AI) |
| `Platform/AndroidHooks.cs` | 원본에 `#if ANDROID` 로 넣은 줄이 부르는 곳(도구 목록 · 배경 그림) |
| `Platform/MpegVideo.cs` · `native/` | 파트1 엔딩(MPEG-1) 해독기 — pl_mpeg(MIT), CI 가 NDK 로 ABI 마다 굽는다 |
| `Platform/ReleaseNotesTrim.cs` | 싣는 릴리즈 노트를 최근 몇 대목으로 자른다(긴 글은 글자 단위로 그려 느리다) |
| `devtools/` | 타입 검사(`check.py`), 헤드리스 시험기(`sim/`), 도구 설치(`setup-toolchain.sh`) |
| `pc-script/` | PC 에서 원본 폴더를 zip 으로 묶는 스크립트(시험용 · 폰으로 옮기기용) |
| `docs/` | 이 문서 · 계획 · 검수 · iOS 참고 · 시안 그림(`mockup/`) |

## 4. 빌드 · 릴리즈

- **CI**(`.github/workflows/android.yml`): 안드로이드 관련 파일을 브랜치에 밀면 APK 를 굽고 Actions 아티팩트로 남긴다.
  `android-v*` 태그를 밀면 같은 APK 를 그 태그 이름으로 Releases 에 올린다. 앱 판 번호는 태그에서, 브랜치 빌드는 `APP_VERSION`.
  작업 환경이 태그를 밀 수 없으면(클라우드 세션은 작업 브랜치에만 밀 수 있다) Actions 에서 「Android APK」 워크플로를 손으로 돌리며
  `release` 칸에 `android-vX.Y.Z` 를 넣는다 — 워크플로가 그 커밋에 태그와 Releases 를 만든다.
  릴리즈 설명은 `docs/안드로이드-릴리즈노트.md` 의 「## android-vX.Y.Z」 대목 — 태그를 밀기 전에 맨 위에 새 판 대목을 적고, 다음 판 번호로 `APP_VERSION` 을 올린다.
- 서명은 러너가 그때그때 만드는 디버그 키 — 새 판을 깔 때 옛 앱을 지워야 할 수 있다(세이브 · 설정은 사용자 자료 폴더에 있어 안 지워진다).
- 로컬에서는 굽지 않는다(안드로이드 워크로드 없음). 대신:
  - 타입 검사: `TOOLS=~/twg-tools python3 WarOfGenesis.Android/devtools/check.py WarOfGenesis.Android/WarOfGenesis.Android.csproj` → `errors: 0`
  - 도구 설치: `devtools/setup-toolchain.sh`(dotnet · csc · 참조 dll 을 `TOOLS` 폴더에)

## 5. 헤드리스 시험기 (`devtools/sim`)

APK 와 같은 소스를 리눅스에서 돌린다(안드로이드 API 를 쓰는 `Droid/` · `MainActivity.cs` 만 빼고 `SimMain.cs` 를 넣는다).
글자는 PIL 도우미(`pilserver.py`), 소리는 재생 시간만큼 기다리는 가짜, 화면은 PNG.

```
TOOLS=~/twg-tools python3 WarOfGenesis.Android/devtools/sim/build.py      # → 출력 폴더(a · b 번갈아)
dotnet <출력>/sim.dll <setup.txt> <결과 폴더> <대본>
```

- `setup.txt`: `part2=…` · `part1=…` · `data=…` 세 줄(원본 폴더와 자료 폴더).
- 대본 명령: `wait 초` · `shot 이름` · `click x y` · `tap x y`(폰 탭과 같은 묶음) · `drag x1 y1 x2 y2` · `key ESC` · `menu 명령번호` · `pad 단추 초` ·
  `cam`(전투 카메라) · `movie N` · `ending` · `bgm …` · `mem` · `files` · `menus` · `audio`.
- 원본 시험 스위치: `DUELDX_TITLE=0`(타이틀 건너뛰기) · `DUELDX_BATTLE=번호` · `DUELDX_AUTOPLAY=1` · `DUELDX_TESTRUN=N`(한 틀에 N 번 갱신 + 기록 `/tmp/dueldx_trace.log`).
- 자료 폴더의 `last-part.txt` 가 1 이면 파트1 타이틀부터 켜진다(파트2 오프닝 시험 때 주의).

## 6. 원작 업데이트 합치기 (판마다)

`포팅-계획.md` 「원본 병합 점검」 그대로:
1. `git fetch upstream main --tags` → 새 `v*` 태그를 합친다.
2. 새 윈도우 호출이 생겼나: `git diff <옛 태그> <새 태그> -- '*.cs' | grep -E 'DllImport|LibraryImport'` — 있으면 대용품을 만든다.
3. 원본을 고친 파일(`포팅-계획.md` 목록)과 겹치나, 갈아 끼운 파일(csproj Exclude)의 원본이 바뀌었나 본다.
4. 타입 검사 → 시험기로 타이틀 · 전투 자동 진행 → APK.
5. iOS 포팅(sonicusers/twgios) 릴리즈 노트도 본다 — 같은 PC 판 코드를 모바일에서 돌려 같은 문제가 난다(그 저장소는 라이선스가 없어 **방법만** 참고, 코드는 안 가져온다).

## 7. 사용자 결정 (요약)

- 뺀 기능: 자동 업데이트 · 버그 리포트/통계 · 편집기 · 고해상도 배경 AI. 원작자 추가 자료는 앱이 받지 않고 사용자 zip 에 넣는다.
- 조작: 터치 + 패드(PC 판 패드 조작 그대로). 패드가 없을 때만 화면 양옆 단축 아이콘. 키보드 단추 · PC 메뉴줄 없음.
- 시스템 메뉴의 「버그 리포트」 자리 → 「도구」(PC 메뉴줄의 도구 · 개발 목록 + 「원본 폴더 다시 고르기」, 「패치 내역」은 뺌).
- 설정 > 화면: 「전체화면」 줄 대신 「배경 그림」(검은 여백을 채울 그림 · 크기 · 투명도). 화면비는 게임 설정의 해상도로 고른다.
- 런처: 「폴더 고르기」 하나 — 이름이 조금 달라도 안의 파일로 알아본다. 원본 폴더 안에 자료 폴더를 만들지 않는다.
- 파트1 엔딩: `Ending.pak`(MPEG-1)을 앱 안 해독기로. 파트1 BGM 15 · 29: mp3 를 기기 해독기로.
- 앱 아이콘: 용 + III + 「THE WAR OF GENESIS 3」(docs/mockup/appicon-512.png).
- 게임 안 「종료」 · 최근 앱에서 밀어 닫기 = 프로세스까지 끝낸다.

## 8. 알려진 것 · 남은 확인

- **기기 확인 남음**: 파트1 배경음악 15 · 29(mp3) 소리 — 사용자가 천천히 하며 본다.
- 파트2 오프닝(모드 > 엔딩 영상)은 기기에서 나온다. 예전 까만 화면은 끝난 게임 프로세스에 다시 붙은 탓이었다(고침).
- 대사 빠짐(파트2 Btl 20137 사건 5, 따라오는 병사 대사)은 원작 문제로 보여 사용자가 원작자에게 알린다.
- 메모리: 시험기 기준 RSS 330~420MB. 뒤로 가면 정리(가장 센 GC), Mono 힙 소프트 한도 192MB(`Environment.txt`).
- 디버그 키 서명 — 정식 서명 키로 바꾸면 그 뒤로는 덮어 깔기만 된다(키를 잃으면 못 덮는다).

## 9. 기기 시험 체크리스트 (새 판마다)

1. 런처: 폴더 고르기 → ✔ 표시 → 게임 시작. 다시 켜면 곧장 게임.
2. 파트2 · 파트1 타이틀, 오프닝(켰을 때), 이야기 · 전투 한 판, 저장 · 불러오기.
3. 터치: 탭 · 길게 누르기 · 두 손가락, 모드 창 탭을 눌러도 맵이 안 밀림. 패드: 이동 · 결정 · 취소 · 시스템 메뉴.
4. 소리: 배경음악 · 효과음, 홈으로 갔다 오면 멈췄다 이어짐.
5. 다른 앱에 몇 분 다녀와도 게임 유지. 최근 앱에서 밀어 닫으면 완전히 꺼지고, 다시 켜면 정상.
6. 파트1 엔딩(마지막 챕터) · 도구 목록 · 배경 그림.
