## 시험용 원본 자료 (2026-11-11)

- 원본 크기(사용자 PC): 파트1 약 1.4GB(압축 약 800MB) · 파트2 약 1.9GB(압축 약 1.4GB).
- 이 공개 포크는 그대로 공개로 둔다(포크는 비공개로 못 바꾸고, 공개 저장소의 Actions 는 무료 · 무제한).
- 시험용 자료는 **따로 만든 비공개 저장소의 릴리즈**에 zip 으로 붙인다(파일 하나 2GB 까지 — 파트별 1개씩이면 된다).
  원작자 릴리즈 꾸러미(`AssetDownload` 대상)도 같은 zip 에 넣는다. 공개 저장소 · 공개 릴리즈에는 절대 넣지 않는다.
- 세션이 비공개 릴리즈를 받을 수 있는지는 실제로 해 보고 확인한다(안 되면 PC 폴더 원격 연결로 바꾼다).

### zip 만들기 (`pc-script/`)

- PC 에서 `pc-script/자료-zip-만들기.bat` 을 두 번 누른다 → 파트1 · 파트2 폴더를 고른다 → 바탕화면 `창세기전-안드로이드-자료/` 에 zip 이 생긴다.
- zip 안의 자리: `part1/…`(파트1 폴더 전체) · `part2/…`(파트2 폴더 전체) · `assets/…`(원작자 pack.json 의 tier 90 이상 = 찾을 때 받는 것, 약 682개 · 800MB).
  앱 · 시험기는 이 셋을 한 폴더에 풀어 쓴다.
- 원본 폴더에서는 `.exe .dll .ocx .sys .msi .com .scr` 만 뺀다 — 리메이크 코드는 이것들을 읽지 않는다(2026-11-11 확인).
  게임이 여는 폴더가 넓어서(`OriginalGame.Locate` 의 `data/<폴더>` 등) 파일을 골라 담지 않고 폴더 전체를 담는다.
- zip 하나는 1.9GB 를 넘지 않게 `-01`, `-02` … 로 나눈다(파일 하나를 쪼개지는 않는다).
- 리눅스 pwsh 7.6 으로 가짜 폴더 · 원작자 자료 3개로 시험함. 윈도우 PowerShell 5.1 실제 실행은 사용자 PC 에서 확인할 것.

## 게임 본체를 붙인 방식 (2026-11-12)

원본 duel-dx · WarOfGenesis.Assets 를 **통째로 링크**하고, 윈도우 부품만 같은 이름의 작은 대용품으로 받는다(`Platform/`):

| 원본이 쓰는 것 | 대용품 | 하는 일 |
|---|---|---|
| Win32(창 · 메시지 · 메뉴 막대 · 키 상태) | `Platform/Win32.cs` (원본 `Win32.cs` 는 링크 안 함) | 메시지 줄 · 메뉴 나무(☰ 단추가 보임) · 60Hz 틀 맞추기 |
| Direct3D11(Vortice) | `Platform/Vortice.cs` | 판 셰이더 글에서 배율 · 자리를 읽어 CPU 로 늘려 찍기 + UI 층 사각형 · 알파 섞기 → 뒷버퍼 → 화면 |
| GDI+(System.Drawing) | `Platform/Drawing.cs` + `Droid/AndroidPlatform.cs` | 글자 = 안드로이드 Paint(기본 한글 글꼴, 파트1 G3Han.ttf 는 원본 폴더에서), 그림 읽기 = BitmapFactory, PNG 쓰기 |
| WinForms(MessageBox · TaskDialog · 폴더 창) | `Platform/Forms.cs` | 안드로이드 대화 상자. 폴더 고르기는 앱 첫 화면 |
| XInput · waveOut · MediaFoundation | `Platform/GamePad.Android.cs` · `Platform/AudioMixer.Android.cs` · `Droid/AndroidPlatform.cs` | 패드 → XInput 상태(원본 패드 조작 그대로), AudioTrack, MediaCodec |
| 뺀 기능 | `Platform/Removed.cs` | 업데이트 · 편집기 · 버그 리포트 · 고해상도 배경 AI — 부르면 알림만 |

**원본 파일을 고친 곳(병합 때 살필 것)** — 모두 `#if !ANDROID` 로 DllImport 줄만 가렸다:
`duel-dx/System/GamePad.cs`, `duel-dx/System/GamePad.Focus.cs`, `WarOfGenesis.Assets/AudioMixer.cs`(+ `partial`).

- 4:3 / 16:9 = 원본 **설정 > 화면 > 해상도**(1280×960 · 1280×720 · 1600×900 · 1920×1080 …). 앱은 기기 화면 크기를 「모니터」로 알린다.
- 「패치 내역」은 원본 줄바꿈이 글자마다 그림을 다시 그려 폰에서 멈춘다 → APK 에 싣는 노트를 새 판 6 대목만(`Platform/ReleaseNotesTrim.cs`, iOS i4 와 같은 처치).
- 헤드리스 시험기: `devtools/sim/build.py` → `dotnet sim.dll setup.txt 결과폴더 대본` (글자 · 그림은 PIL 도우미 `pilserver.py`). 원본 시험 스위치
  `DUELDX_TITLE=0 DUELDX_BATTLE=153 DUELDX_AUTOPLAY=1` 로 전투 자동 진행.
- 시험기로 확인(2026-11-12, 실제 원본 자료): 타이틀 · 에피소드 고르기 · 이야기(대사 · 초상 · 필드) · 전투 16턴 자동 진행 · 설정 창 · 패치 내역 · 파트1 타이틀 ·
  해상도 16:9 바꾸기 · 메뉴 막대 · 소리 믹서 실시간 출력.

## 원본 병합 점검 (원본 업데이트를 받을 때마다)

1. `git fetch upstream main --tags` → 새 `v*` 태그를 병합.
2. **새 윈도우 호출이 생겼나**: `git diff <옛 태그> <새 태그> -- '*.cs' | grep -E 'DllImport|LibraryImport'` —
   iOS 판이 원본 v1.0.72 의 `SetThreadExecutionState` · `GetDpiForWindow` 로 시작하자마자 죽었다(docs/iOS-포팅-참고.md i2).
3. 새 파일 · 갈아 끼운 파일의 원본이 바뀌었나 확인 → 안드로이드 APK 를 다시 굽는다.
4. iOS 포팅(sonicusers/twgios) 릴리즈노트도 본다 — 같은 PC 판 코드를 모바일에서 돌리므로 같은 문제가 난다.

## 도구

`devtools/` 는 cds-remake `CostaDelSol.Android/devtools/` 에서 복사했다(아직 대항해시대용 — 이 게임에 맞게 고쳐 쓴다).
